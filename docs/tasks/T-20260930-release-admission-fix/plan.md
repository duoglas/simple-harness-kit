# 修复验证复用与交付目标边界并完成补丁发布

## 目标

修复发布复审在 v0.15.0 中复现的准入与交付边界缺口，使风险升级、控制面漂移、未满足前置条件、跨仓库交付和不完整需求均不能复用旧证明获得准出。

## 阶段

1. SETUP：复现旧行为并增加纯函数与真实临时 Git/CLI 负控。
2. EXECUTE：修复验证准入、通配必填字段和 Git 目标绑定；代码与测试分开提交。
3. VERIFY：运行专项、两项旧任务 E2E、完整发布门禁及真实 runtime/browser 测试。
4. REVIEW：冻结候选，双独立审查全部已报告问题；补齐 release notes 与旧任务结项。

## 边界与不可逆项

- 已存在的 v0.15.0 tag 保持不变；通过全部验证后以 v0.15.1 发布补丁。
- 只修改通用 SHK 产品逻辑；环境和跨仓库流程留在工作台。
- 用户已授权完成后续工作，包括必要修复、提交和发布收尾；浏览器回归使用现有 Playwright 已获单独授权。
- CI workflow 新建和历史本地分支/备份删除不属于本次发布修复。
- 用户在第三轮审查升级后明确回复“继续”，授权追加一轮修复和双独立复审；此前的失败记录保留。
- 用户明确将 N/A 契约与发布流程修复纳入本次：仅 build/types/lint/coverage 可显式声明原因，关键发布证明仍须 PASS。
- 第六轮再次升级人工后，用户明确回复“继续”，授权按 `review/next-repair-plan.md` 修复剩余 7 项，再做独立复审和完整发布门禁。

## 验收标准

- 同候选低风险或缺检查的 baseline 不得授权高风险/发布复用，合法同范围 baseline 仍可复用。
- 配置的控制面摘要漂移与不满足冻结/review 前置条件均拒绝复用。
- 通配必填字段逐元素验证，任一缺字段拒绝 shipped，完整和 draft 正控通过。
- 另一仓库的 commit/tag/push 不能消费本仓证据；隐式多 tag 推送被拒绝。
- 新增回归在旧代码失败、修复后通过；完整发布门禁无 required FAIL/WARN/SKIP/DEGRADED。
- 两位独立 reviewer 在修复候选上均无阻断问题，旧任务才可结项。
- N/A 单列且绑定当前契约；配置漂移、命令冲突和关键检查豁免均拒绝，兼容行为不变。
- 版本检查读取远端实际 SHA 的普通文件；离线 SKIP 不得变成发布 PASS。本地错指或缺失的同名 tag 不能代替远端证明。
