# v0.15.1 — 修复验证复用与交付目标绑定

v0.15.0 发布复审发现：低风险 full 结果可能被更高风险验证复用；Git 切换执行仓库或附带标签时，证据没有覆盖实际交付对象。本补丁补齐这些边界，同时修复部分需求缺字段仍能结项的问题。

## 修复

- 复用必须覆盖请求风险、必需检查及其状态语义，并比较配置的 runner、verdict、scheduler 身份。
- 冻结和 review 前置条件同时约束 RUN 与 REUSE。
- 通配必填字段逐元素校验，缺失分支不会被有效元素掩盖。
- Git/wrapper 改变执行上下文后必须仍指向已验证仓库；无法确认时拒绝。
- 检查 Git 可执行回调、实际参数与完整暂存区提交语义；同一命令先改变候选再交付时拒绝复用执行前证据。
- 附带标签与递归子模块推送在没有逐 ref 证明时拒绝，包括相关有效 Git 配置。
- 仅 build/types/lint/coverage 支持显式说明原因的 N/A；配置命令存在时必须执行。新式证据与普通缓存均绑定实际证明输入，陈旧证据拒绝交付但不阻止生成新证据。
- 升级入口校验 origin 实际对象；离线 SKIP 阻止发布，先发布新 tag 再独立推进默认入口。

## 发布验收口径

发布必须通过双独立审查，并在已提交、清洁且与远端同步的候选上完成 release 验证和 `tests/pre-release-check.sh`。验收包括任务 E2E、真实浏览器及 mutation、OSS dogfood、Codex runtime 与 selftest。失败的历史验证和复审记录保留在修复任务中；局部补验不能替代完整发布门禁。最终实测结果随 GitHub Release 发布。

build、types、lint、coverage 未配置，按显式声明记为 NOT_APPLICABLE，不算 PASS 或覆盖率达标。

Git 身份探测目前不支持配置了非空 clean/process filter 的仓库（含已填充子模块），会报告身份不可用，不执行这些回调。Git 扩展和未支持的可执行配置也会被门禁拒绝；支持范围见 [证据说明](../evidence-attestation.md)。

## 版本关系

既有 v0.15.0 tag 保持不变。本补丁通过全部门禁后作为推荐版本发布。

发布先创建已验证的新 tag，再以独立提交推进 master 上的升级默认版本。因此 v0.15.1 标签内的 `upgrade.sh` 默认仍指向 v0.15.0；新 tag 发布后，使用 README 中的 master 升级入口，或显式传入 `--ref v0.15.1`。
